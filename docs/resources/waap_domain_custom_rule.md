# gcore_waap_domain_custom_rule (Resource)

WAAP custom rules allow, block, challenge, monitor or tag requests to a domain when all of their conditions match.

A rule triggers when all of its conditions match. Each entry of `conditions` sets exactly one condition type, and a
rule takes between 1 and 5 conditions. A `request_rate` condition must be the only condition of its rule. Set
exactly one kind in `action`. The `allow`, `captcha`, `handshake` and `monitor` actions take no settings: write them
as `{}`. The API ignores any keys inside them, so a non-empty value shows a change on every plan.

The API stores some values in a canonical form, and the provider rejects any other form at plan time so the rule
does not drift: IP addresses in canonical notation (`2001:db8::1`, not `2001:DB8:0::1`), JA3 and JA4 fingerprints
in lowercase, country codes in uppercase, and no leading or trailing whitespace in `name`, header values, tags
and content types.

## Example Usage

### Block a path

```terraform
# Block POST requests to /admin from outside the office range for one hour
resource "gcore_waap_domain_custom_rule" "block_admin" {
  domain_id   = 12345
  name        = "Block admin from outside office"
  description = "Only the office may post to /admin"
  enabled     = true

  action = {
    block = {
      status_code     = 403
      action_duration = "1h"
    }
  }

  conditions = [
    { url = { url = "/admin", match_type = "Contains" } },
    { http_method = { http_method = "POST" } },
    { ip_range = { lower_bound = "192.0.2.0", upper_bound = "192.0.2.255", negation = true } },
  ]
}
```

### Rate limit

```terraform
# Show a captcha to clients that send more than 100 API requests in 10 seconds.
# A request_rate condition must be the only condition of its rule.
resource "gcore_waap_domain_custom_rule" "rate_limit" {
  domain_id = 12345
  name      = "API rate limit"
  enabled   = true

  action = {
    captcha = {}
  }

  conditions = [
    {
      request_rate = {
        path_pattern = "^/api/"
        requests     = 100
        time         = 10
        http_methods = ["GET", "POST"]
      }
    },
  ]
}
```

### Tag requests

```terraform
# Tag requests from hosting providers in selected countries, for use in other rules
resource "gcore_waap_domain_custom_rule" "tag_hosting" {
  domain_id = 12345
  name      = "Tag hosting traffic"
  enabled   = true

  action = {
    tag = {
      tags = ["hosting"]
    }
  }

  conditions = [
    { owner_types = { owner_types = ["HOSTING_SERVICES"] } },
    { country = { country_code = ["CN", "RU"] } },
  ]
}
```

### Migrating from the v0 `gcore_waap_custom_rule` resource

The v0 resource grouped conditions by type in a single `conditions` block and used blocks for the action. Here
`conditions` is a list with one condition per entry, and `action` is an object. The rule IDs are the same:

```terraform
# v0
resource "gcore_waap_custom_rule" "example" {
  domain_id = 12345
  name      = "Block admin"
  enabled   = true
  action {
    block {
      status_code = 403
    }
  }
  conditions {
    url {
      url = "/admin"
    }
    ip {
      ip_address = "192.0.2.10"
      negation   = true
    }
  }
}

# now
resource "gcore_waap_domain_custom_rule" "example" {
  domain_id = 12345
  name      = "Block admin"
  enabled   = true
  action = {
    block = {
      status_code = 403
    }
  }
  conditions = [
    { url = { url = "/admin" } },
    { ip = { ip_address = "192.0.2.10", negation = true } },
  ]
}
```

Import the existing rule with an `import` block, using `<domain_id>/<rule_id>` instead of the v0
`<domain_id>:<rule_id>`. Remove the v0 resource from v0 state (`terraform state rm`) instead of destroying it, so
both providers never manage the same rule.

Older rules can have `response_header` or `response_header_exists` conditions. The API no longer accepts them on
create or update, so this resource cannot represent them. Import warns about each one, and the next apply that
changes the rule removes it.
