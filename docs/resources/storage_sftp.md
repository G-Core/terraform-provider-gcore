# gcore_storage_sftp (Resource)

SFTP storages provide file transfer protocol access for securely uploading, downloading, and managing files over SSH.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.11" # write-only arguments
  required_providers {
    gcore = { source = "G-Core/gcore" }
  }
}

variable "sftp_password" {
  type      = string
  sensitive = true
  ephemeral = true
}

resource "gcore_storage_sftp" "example_storage_sftp" {
  location_name          = "s-region-1"
  name                   = "my-sftp-storage"
  password_wo            = var.sftp_password
  password_wo_version    = 1
  expires                = "2 years 6 months"
  has_custom_config_file = false
  is_http_disabled       = false
  server_alias           = "my-storage.example.com"
  ssh_key_ids            = [1, 2, 3]
}
```

-> **`location_name` must be a storage location available to your account.** The example uses a placeholder.
List your locations with the `gcore_storage_locations` data source and select one that supports SFTP. Changing the
location replaces the storage.

## Managing the password

`password_wo` is write-only, so Terraform does not store it in state or plan files. Write-only arguments require
Terraform 1.11 or later. Set `password_wo` and `password_wo_version` together, or omit both.

| Change | Result |
|---|---|
| Add both arguments | Sets or replaces the password in place |
| Change `password_wo_version` | Rotates the password in place |
| Change only `password_wo` | No change; Terraform cannot compare write-only values |
| Remove both arguments | Clears a password previously managed by Terraform |
| Omit both after import or upgrade | Leaves the existing password unchanged |
| Password removed outside Terraform | Reapplies the configured password on the next apply |

`password_wo_version` is the only rotation trigger. Change it whenever the password changes. When the password comes
from a secret store, use the secret's version so both values change together.

Password changes do not replace the storage or its contents. The SFTP server can take about a minute to apply a
password change.

### Existing and external passwords

Terraform does not manage a password found during import or upgrade unless you configure both password arguments.
Adding the pair replaces that password in place and produces a warning. To clear it through Terraform, add the pair
first, apply, and then remove both arguments.

If someone changes a password outside Terraform, the provider cannot detect the new value. The configured password is
used again only after `password_wo_version` changes. If someone removes the password, the next apply restores the
configured value.

~> **Do not set `TF_LOG=DEBUG` during password changes.** Debug logs contain raw API requests and responses, including
the password and API key. If such a log was created, rotate both secrets.

## Upgrading from `password_mode`

Earlier versions used `password_mode`, `sftp_password`, and a computed `password`. Remove the old arguments from the
configuration. The provider drops the old fields from state without replacing the storage. Run
`terraform apply -refresh-only` to save the cleaned state.

Passwords created with the old `auto` or `set` modes remain active but are not managed by Terraform. Configure
`password_wo` and `password_wo_version` to replace one in place.

!> **Rotate passwords created with the old `auto` or `set` modes.** Earlier provider versions stored them in cleartext
in Terraform state and its backups. Use a new password when adding the write-only arguments.

## Schema

### Required

- `location_name` (String) Location code where the storage should be created
- `name` (String) User-defined name for the storage instance

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `expires` (String) Duration when the storage should expire (e.g., "2 years 6 months"). Omit for no expiration.
- `has_custom_config_file` (Boolean) Whether this storage should use a custom configuration file
- `is_http_disabled` (Boolean) Whether HTTP access should be disabled (HTTPS only)
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) SFTP password (8-63 chars). This is a write-only field — it is sent to the API but never stored in state or plan artifacts. Set it together with `password_wo_version`. Change the version to send a new password; the storage is updated in place. Editing `password_wo` alone produces no plan. Remove both arguments to clear password authentication in place. Omit both to create a storage with SSH-key-only access.
- `password_wo_version` (Number) The version of `password_wo`. Terraform never sees the password value, so this number is what tells it the password changed: change it (conventionally increment) to re-send `password_wo` to the API in place — a rotation, or the first password on a storage that has none or one Terraform did not set. Editing `password_wo` alone is not detected. Remove it together with `password_wo` to clear password authentication in place. Never causes a replacement.
- `server_alias` (String) Custom domain alias for accessing the storage. Omit for no alias.
- `ssh_key_ids` (List of Number) SSH key IDs to associate with this storage at creation time. If omitted, no keys are linked.

### Read-Only

- `address` (String) Full hostname/address for accessing the storage endpoint
- `created_at` (String) ISO 8601 timestamp when the storage was created
- `full_name` (String) Read-only internal full name of the storage, composed as "{`client_id`}-{name}".
Used by the SFTP backend as the login username. Clients should use this value when connecting
but should continue to identify the storage by `name` in their own configuration.
- `has_password` (Boolean) Whether password authentication is configured for this storage. Refreshed on every read; if it becomes false while `password_wo` is configured, the next apply re-applies the password.
- `id` (Number) Unique identifier for the storage instance
- `provisioning_status` (String) Lifecycle status of the storage. Use this to check readiness before operations.
Available values: "creating", "active", "updating", "deleting", "deleted".


## Import

Import is supported using the following syntax:

```shell
$ terraform import gcore_storage_sftp.example '<storage_id>'
```

~> Import does not manage the existing password. Configure both password arguments to replace it in place, or omit
both to leave it unchanged.
